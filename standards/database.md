# Database standards

Apply to SQLite (POC) and PostgreSQL (production). Write SQL that runs on both unless a comment says otherwise.

## Naming
- Tables plural snake_case (`applications`, `render_log` is the exception: it is a log, singular); columns snake_case.
- Primary key column is `id`; foreign keys `<table_singular>_id`; booleans `is_<x>`; timestamps `<x>_at` in UTC.
- Constraints and indexes named: `pk_<table>`, `fk_<table>_<ref>`, `uq_<table>_<cols>`, `ix_<table>_<cols>`.

## Keys and identity
- Every primary key is a UUID v4 generated by the application, stored as `TEXT` (36) in SQLite and `uuid` in PostgreSQL.
- No natural keys as primary keys; uniqueness via `uq_` constraints (`uq_template_versions_template_number`).
- Never expose sequential ids.

## Tenancy columns (mandatory)
- Account-scoped tables carry `account_id NOT NULL`; application-scoped tables carry `application_id NOT NULL`
  (and `account_id` when a query needs it without a join).
- Every query on these tables includes the tenancy column in `WHERE`; repositories take the tenant id as a parameter,
  never read it from the row.
- Composite indexes lead with the tenancy column: `ix_render_log_application_created (application_id, created_at DESC)`.

## Migrations
- One numbered file per change under `src/PdfFill.Api/Data/migrations/NNNN_<name>.sql`; forward-only; idempotent where cheap.
- `schema.sql` is the current full schema and must equal the result of applying all migrations (CI check planned).
- Destructive changes (drop, rename) ship in two steps: add + backfill, then remove in a later release.

## Data types and JSON
- Money as integer minor units; percentages as `REAL`; never `FLOAT` for money.
- JSON columns (`fields_json`, `mapping_json`, `payload`, `problems`) are `TEXT` in SQLite, `jsonb` in PostgreSQL;
  the application validates the shape, the database does not.
- Enumerations (`status`) as short lowercase strings with a `CHECK` constraint.

## Retention and deletion
- Soft delete with `deleted_at` for account-visible entities (applications, templates); hard delete only through
  retention jobs or explicit account deletion.
- `render_log.payload` and `output_ref` are purged by the retention job; the row stays for usage and audit.
- Every table with retention has `created_at` indexed.

## Performance
- Paginate with keyset (`created_at, id`) cursors, never `OFFSET` on logs.
- Store PDF bytes in the database only in the POC; production uses object storage with a reference column.
- Add an index only with a query that needs it; note the query in the migration comment.
